# Founder PCB first start - 2026-11-12

Firmware target: `grova_founder_s3` on branch `codex/founder-pcb-bringup`.
The PCB has not yet been connected/accepted in this chat. Prepare all tests with
loads disconnected initially. This is the new S3 board, never Cube 001 or 002.

## 1. Power and boot

Check that the delivered board matches the versioned schematic and N16R8 module.
Use the schematic power selection: H2 selects USB vs external 5V supply;
do not assume all 12V output functions are powered from USB alone.
Verify the GPIO46/RTC_INT/R58 issue with the actual PCB before relying on
manual BOOT/RESET entry. Normal flash boot ignores GPIO46 when GPIO0 is HIGH;
manual joint USB/UART download requires both LOW. Automatic USB Serial/JTAG
entry is a separate path and does not prove manual recovery works. No code
change can repair the initial reset-time strap. No hardware rework is assumed.

## 2. First flash

From the firmware repository, after confirming the new board's actual COM port:

```powershell
C:\Users\Kai\.platformio\penv\Scripts\pio.exe device list
C:\Users\Kai\.platformio\penv\Scripts\pio.exe run -e grova_founder_s3 -t upload --upload-port COM7
C:\Users\Kai\.platformio\penv\Scripts\pio.exe device monitor --port COM7 --baud 115200
```

COM7 is an example, not a detected device. No upload has been performed.
The normal upload writes boot components and the app with their correct offsets.
An optional prebuilt first-flash package is generated by
`python tools/package_founder.py`; consult its README and manifest before use.
Do not erase flash or reuse the merged first-flash image for ordinary updates
of a configured board: that would discard provisioning data.

## 3. OLED and Wi-Fi

Use the dedicated system OLED connector (root bus, SDA GPIO8/SCL GPIO9), not a
mux expansion port. Check its pin order GND/VCC/SDA/SCL against the module.
The attached module is specified as SSD1317, 64x128. The firmware supports
rotation and COM offset; exact panel mapping requires a real visual test.
The module must include its own required display power circuitry.

The first start remains in Rest. OLED should show `GROVA-<12 hex MAC digits>`,
the setup key and AP IP. Connect the phone to that protected WLAN, open the
shown IP, enter the key, scan and save the home WLAN. Credentials are committed
only after a successful connection test. Open the new LAN IP for board controls.

If the OLED stays blank, use USB console:

```text
status
setup
display 0 80
```

`setup` explicitly prints the same AP credentials so OLED failure does not
block phone setup. `display <rotation> <offset>` changes only display settings;
rotation is 0..3, offset 0..95. The default offset 80 is provisional from a
64-MUX reference panel, not confirmation of the exact module layout.

## 4. Peripheral checks

- `status`: confirm 16 MB flash and 8 MB PSRAM, output readiness, mux and RTC.
- Connect the selected supported climate sensor on one mux port, then inspect
  its channel/address and temperature/humidity. Do not guess connector order.
- After Internet/NTP synchronization, check RV-3032 valid time and write status;
  verify time retention with the real battery and a complete power interruption.
- Outputs remain zero in Rest. Release Rest deliberately, then test each neutral
  switch and each analogue setpoint individually with a meter before a load.
- In Rest, use **Geraete zuordnen** to select the real load profile, supply
  voltage and compatible output. Follow [the device catalog](founder-equipment.md).
  Pump profiles have a 10-minute boot lock and a maximum 10-second pulse. Measure
  actual cutoff and confirm reset/Rest/setup/OTA leave the load off.
- Test both fan PWM/tacho paths with actual connected fans; verify fault and
  zero-command behaviour of those fans rather than assuming zero means stopped.
- Hold CONFIG five seconds: Rest and setup recovery should activate without
  deleting the last validated WLAN. Confirm recovery on phone and OLED/USB.

Record actual findings, including any failed step. Software tests do not close
these physical checks. ADC/OneWire/RS485/safety contact functions and the future
automation engine are not enabled by this first-start software.
